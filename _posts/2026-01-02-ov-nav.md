# Open-Vocabulary Navigation: From CLIP-Based Maps to Embodied Foundation Models

## Introduction

For a robot to operate naturally in a human environment, it needs to understand more than geometry.

A conventional navigation system can answer questions such as _"Where am I?"_, _"Where can I move?"_, and _"What path should I take?"_. But a household robot needs to answer a different class of questions:

> _"Go to the kitchen and bring me the apple from the counter."_

This instruction requires the robot to connect language to the physical world. It must understand what an _apple_ is, determine where an apple is likely to be, understand what a _kitchen_ and a _counter_ are, and ultimately translate this semantic understanding into a navigable location.

This problem is generally studied under **Vision-and-Language Navigation (VLN)** and, more specifically, **open-vocabulary object navigation (OVON/ObjectNav)**. The central challenge is to move from navigation based on predefined semantic categories toward navigation where the robot can understand arbitrary natural-language descriptions.

The emergence of large vision-language models such as CLIP has significantly changed how this problem can be approached. Instead of training a navigation system to recognize a fixed set of objects, researchers began using pretrained vision-language representations to give robots a much more open-ended semantic understanding of their surroundings.

This post traces that progression—from CLIP-based semantic maps, to compact 3D scene graphs, to foundation-model-driven exploration and LLM-based planning—and discusses where open-vocabulary navigation appears to be heading.

---

## 1. What makes navigation "open-vocabulary"?

Traditional object navigation systems are usually trained around a fixed set of semantic categories.

For example, a robot might be trained to find:

```text
chair
table
bed
sofa
toilet
refrigerator
```

The robot can then receive an instruction such as:

> "Find the refrigerator."

But this vocabulary is determined by the training data. If the robot encounters an object outside the predefined categories, the navigation system has no natural way of reasoning about it.

Open-vocabulary navigation changes the interface.

Instead of asking the robot to navigate toward one of a fixed set of classes, we can provide arbitrary language:

> "Find something I can use to open a bottle."

or

> "Go to the table where the person left their coffee."

The system therefore needs a representation in which **visual observations and language occupy a shared semantic space**.

This is where CLIP became particularly influential.

---

# 2. CLIP changes the interface between vision and language

CLIP learns a joint embedding space for images and text. An image and a textual description can therefore be compared using their embedding similarity.

Conceptually:

```text
                 CLIP
                  │
       ┌──────────┴──────────┐
       │                     │
    image                  text
       │                     │
       ▼                     ▼
  image embedding       text embedding
       │                     │
       └──────── similarity ─┘
```

For navigation, this provides an attractive mechanism for grounding language in visual observations.

Instead of training a detector specifically for:

```text
"chair"
"table"
"mug"
```

we can query the visual representation with arbitrary text.

The question then becomes:

> **How do we take this 2D vision-language representation and turn it into something spatially useful for a robot?**

This led to one of the most important developments in open-vocabulary navigation: **language-grounded spatial maps**.

---

# 3. VLMaps: putting language into a spatial map

**VLMaps** is one of the works that demonstrated a particularly influential formulation of this idea.

The key insight is simple:

> If visual-language features can tell us what pixels represent, why not project those features into 3D space?

Instead of maintaining only a geometric map, the robot maintains a map whose locations also carry semantic information.

Conceptually:

```text
RGB-D observations
        │
        ▼
   visual features
        │
        ▼
     3D mapping
        │
        ▼
┌──────────────────────────┐
│     Semantic 3D Map      │
│                          │
│ kitchen   ─────────────┐ │
│ counter               │ │
│ apple                 │ │
│ table                 │ │
└──────────────────────────┘
        │
        ▼
 "apple on the counter"
        │
        ▼
  map location
        │
        ▼
 classical navigation
```

The important conceptual separation is that **foundation models perform semantic grounding while classical robotics performs geometric navigation**.

The robot can use language to query the semantic map, retrieve a relevant location, and then pass that location to a conventional planner.

This was a powerful idea because it meant that the navigation system did not necessarily need a detector trained for every possible object category.

---

## 4. The problem with dense semantic maps

However, directly attaching a high-dimensional embedding to every point in a 3D map is expensive.

Suppose every point in a scene has a CLIP-like feature vector:

[
\mathbf{f}_i \in \mathbb{R}^{D}
]

For a large environment containing millions of points, this quickly becomes a substantial memory requirement.

More importantly, a point-wise representation does not necessarily capture the **structure of the environment**.

Consider:

```text
kitchen
 ├── counter
 │    ├── toaster
 │    └── apple
 └── refrigerator
```

A collection of independent point embeddings tells us what individual points look like, but not explicitly that:

- the apple is on the counter,
- the counter is inside the kitchen,
- the refrigerator is also inside the kitchen.

These relationships become important when language describes an object using its context.

For example:

> "Find the cup on the table in the kitchen."

Now the robot needs to reason about **entities and their relationships**, rather than simply finding the point with the highest similarity to _cup_.

---

# 5. ConceptGraphs: from dense embeddings to structured semantic memory

**ConceptGraphs** takes an important step in this direction by representing the environment as an **open-vocabulary 3D scene graph**.

Instead of storing a feature vector for every point, the representation is organized around meaningful entities.

A simplified representation might look like:

```text
                  Apartment
                      │
            ┌─────────┴─────────┐
            │                   │
         Kitchen             Living Room
            │                   │
      ┌─────┴─────┐         ┌───┴────┐
      │           │         │        │
   Counter    Refrigerator  Sofa    Table
      │
    ┌─┴──┐
    │    │
   Apple Toaster
```

Each node can retain semantic information, while edges capture spatial or semantic relationships.

This makes the representation much more useful for task-level reasoning.

The robot can now answer queries such as:

> "Where is the apple?"

but also more contextual queries such as:

> "Where is the cup on the kitchen table?"

This idea is closely related to **open-vocabulary 3D scene graphs**, where arbitrary text queries can be grounded to objects, regions, and their relationships.

The broader lesson is that the representation of the world matters just as much as the vision-language model used to construct it.

---

# 6. SayPlan: using LLMs to reason over the world model

Once the environment is represented symbolically, another possibility opens up:

> Instead of using the language model only to identify objects, let it reason about the environment and generate a high-level plan.

This is the direction explored by **SayPlan**.

SayPlan uses 3D scene graphs as a structured representation that an LLM can reason over. Rather than giving the LLM an enormous raw environment, it performs a semantic search over a hierarchical scene graph to identify the portions of the environment relevant to the task.

For example, given:

> "Get the apple from the kitchen."

the LLM can reason at a higher level:

```text
Apartment
    ↓
Kitchen
    ↓
Counter
    ↓
Apple
```

The resulting high-level plan can then be grounded using classical navigation and replanning.

This is important because it illustrates another division of labor:

```text
LLM
│
├── understand instruction
├── reason about semantic relationships
└── generate high-level plan
        │
        ▼
Scene graph
        │
        ▼
Classical planner
        │
        ▼
Robot
```

SayPlan also uses iterative replanning and a classical path planner to keep the LLM's high-level reasoning from having to solve low-level geometric navigation itself.

---

# 7. But there is a fundamental assumption hiding here

There is an important limitation to the map-based approach:

> **The map must accurately describe the current world.**

This is easy to overlook.

Imagine the robot builds this map:

```text
Kitchen
 └── Counter
      └── Apple
```

Later, a person moves the apple:

```text
Kitchen
 ├── Counter
 └── Dining table
       └── Apple
```

The robot's semantic map is now wrong.

This is not unusual in a household. Objects are continuously moved, added, removed, occluded, and manipulated.

Therefore, the problem is not simply:

> **How can I build an open-vocabulary map?**

It becomes:

> **How can I maintain a useful semantic representation of a world that is constantly changing?**

This is one of the major limitations of treating a semantic map as a static database of object locations.

---

# 8. From mapping the world to searching the world

An alternative is to avoid assuming that the target's location is already known.

Instead, the robot can actively search for it.

This leads to a different formulation:

> **Given what I currently see and know, where should I move next to maximize the probability of finding the target?**

The architecture becomes:

```text
             instruction
                  │
                  ▼
          language reasoning
                  │
                  ▼
            target concept
                  │
                  ▼
          current observation
                  │
                  ▼
       candidate directions
                  │
                  ▼
        choose next viewpoint
                  │
                  ▼
              navigate
                  │
                  ▼
         observe environment
                  │
                  └─────────────┐
                                ▼
                         update belief
```

This is fundamentally different from querying a prebuilt semantic map.

The robot is performing **active perception**.

---

# 9. OpenFMNav: foundation models as active search

**OpenFMNav** is a representative example of this direction.

Rather than relying on a predefined closed-set object vocabulary, OpenFMNav uses LLMs to extract the objects relevant to a free-form instruction and VLMs to discover candidate objects in the environment. It constructs what the authors call a **Versatile Semantic Score Map (VSSM)** and uses common-sense reasoning to guide exploration and exploitation.

The important change is that the foundation model is no longer being used only to create a static semantic representation.

It is participating in the **search process itself**.

For example:

> "Find something to eat."

The robot does not necessarily need to have _something to eat_ as an explicit object category in its map.

The language model can reason about likely candidates, while the vision-language model evaluates observations.

This gives a system that can operate in unseen environments without requiring a prebuilt semantic map.

---

# 10. From "Where is the object?" to "Where should I look?"

This distinction is worth emphasizing.

A map-based system asks:

[
\text{Where is } x?
]

An active-search system asks:

[
\text{Where should I look next to find } x?
]

The second question is more appropriate when the environment is unknown or dynamic.

Suppose the instruction is:

> "Find the apple."

The robot might reason:

```text
Apple
 │
 ├── likely: kitchen counter
 ├── likely: dining table
 ├── likely: refrigerator
 └── unlikely: bathroom
```

It can then select an exploration target based on both:

- visual evidence, and
- semantic/common-sense priors.

After every observation, these beliefs can be updated.

This starts to resemble a **partially observable decision-making problem**, rather than simple goal-conditioned navigation.

---

# 11. Two approaches that initially look different

At this point, open-vocabulary navigation can be viewed through two major paradigms.

### Paradigm 1 — Build a semantic representation first

```text
                 Environment
                      │
                      ▼
                perception
                      │
                      ▼
            semantic 3D map
                      │
                      ▼
               language query
                      │
                      ▼
              target location
                      │
                      ▼
             classical planner
```

Examples include:

- VLMaps
- ConceptGraphs
- open-vocabulary 3D scene graphs

The strength is **persistent spatial memory**.

The weakness is that the representation can become stale.

---

### Paradigm 2 — Search using foundation models

```text
             instruction
                  │
                  ▼
          VLM / LLM reasoning
                  │
                  ▼
        current visual observation
                  │
                  ▼
          choose exploration goal
                  │
                  ▼
                move
                  │
                  ▼
              observe
                  │
                  └──────→ repeat
```

Examples include:

- OpenFMNav
- other foundation-model-guided ObjectNav approaches

The strength is **adaptability to unseen environments**.

The weakness is that the robot can repeatedly rediscover the same information and lacks a persistent, structured memory of what it has already learned.

---

# 12. The two approaches are beginning to converge

These paradigms do not necessarily need to compete.

A more general system could combine them:

```text
                    Human instruction
                           │
                           ▼
                    LLM / VLM reasoning
                           │
                           ▼
                  ┌──────────────────┐
                  │ Spatial memory   │
                  │                  │
                  │  objects         │
                  │  rooms           │
                  │  relationships   │
                  │  uncertainty     │
                  │  history         │
                  └────────┬─────────┘
                           │
              ┌────────────┴────────────┐
              ▼                         ▼
       known target              unknown target
              │                         │
              ▼                         ▼
       navigate directly        active exploration
              │                         │
              └────────────┬────────────┘
                           ▼
                     local planner
                           │
                           ▼
                         robot
                           │
                           ▼
                    new observation
                           │
                           └──────→ update memory
```

This is a much more natural architecture for a household robot.

The robot should neither assume:

> _"My map is always correct."_

nor:

> _"I should forget everything and search from scratch."_

Instead, it should maintain a **belief about the environment**, use its memory when useful, and actively gather information when uncertain.

---

# 13. The remaining challenge: persistent world models

This leads to what I believe is the central unresolved problem in open-vocabulary navigation.

A useful representation should simultaneously provide:

### Open vocabulary

The robot should understand arbitrary natural language descriptions.

### Spatial grounding

The concepts need to correspond to actual locations in 3D space.

### Structured relationships

The representation should capture relationships such as:

```text
apple → on → counter
counter → inside → kitchen
kitchen → adjacent_to → dining room
```

### Temporal information

The robot should know:

```text
apple
location: kitchen counter
last observed: 2 minutes ago
confidence: 0.82
```

rather than treating the location as permanent.

### Uncertainty

If the robot has not observed the counter recently, it should know that its belief may be stale.

### Actionability

The representation should ultimately support decisions such as:

> "Where should I go?"

rather than merely:

> "What objects exist?"

This moves the problem beyond **semantic mapping** toward **persistent, dynamic world modeling**.

---

# 14. Why this matters for household robots

Consider a realistic instruction:

> **"Go to the kitchen, find the apple I left on the counter, and bring it to me."**

A complete system needs to perform several forms of reasoning:

```text
Language
    ↓
What does "apple" refer to?
    ↓
Where is the kitchen?
    ↓
Where is the counter?
    ↓
Where was the apple last observed?
    ↓
Is that information still trustworthy?
    ↓
Navigate to the kitchen
    ↓
Search the counter
    ↓
Apple absent?
    ↓
Where is the next most likely location?
    ↓
Explore
    ↓
Detect apple
    ↓
Navigate to a reachable pose
    ↓
Manipulate apple
    ↓
Return to user
```

None of the individual components are completely new.

The difficulty lies in **connecting them into one persistent closed-loop system**.

---

# 15. What foundation models are actually contributing

It is tempting to think that the role of foundation models is simply:

> **"Use a VLM instead of an object detector."**

That undersells their role.

Across these works, foundation models are being used for increasingly different capabilities:

| Capability          | Traditional robotics         | Foundation-model approach                |
| ------------------- | ---------------------------- | ---------------------------------------- |
| Object recognition  | Closed-set detector          | Open-vocabulary VLM                      |
| Language grounding  | Hand-designed labels         | CLIP/VLM embeddings                      |
| Semantic retrieval  | Fixed categories             | Free-form text                           |
| Scene understanding | Explicit labels              | Open-ended concepts                      |
| Spatial reasoning   | Hand-coded relations         | VLM/LLM reasoning                        |
| Task decomposition  | Hand-coded planner           | LLM                                      |
| Exploration         | Heuristic frontier selection | Language/common-sense-guided exploration |
| World knowledge     | Hard-coded                   | LLM/VLM priors                           |

But there is an equally important observation:

**Foundation models have not eliminated the need for classical robotics.**

Geometry, localization, collision checking, path planning and control remain highly valuable.

The emerging architecture is therefore not necessarily:

> **Foundation models replace robotics.**

It is more likely:

> **Foundation models provide semantic and task-level intelligence on top of geometric and control-level robotics.**

---

# 16. Where the field is heading

Looking across VLMaps, ConceptGraphs, SayPlan, OpenFMNav and related work, I see a progression:

```text
CLIP
 │
 ▼
Language-grounded visual features
 │
 ▼
VLMaps
 │
 ▼
Open-vocabulary spatial representations
 │
 ▼
ConceptGraphs / 3D scene graphs
 │
 ▼
LLM reasoning over structured environments
 │
 ▼
SayPlan
 │
 ▼
Foundation-model-guided active exploration
 │
 ▼
OpenFMNav
 │
 ▼
Persistent + dynamic + language-grounded world models
 │
 ▼
Long-horizon embodied agents
```

The central question is gradually changing.

Initially:

> **"Can we associate arbitrary language with locations in the environment?"**

Then:

> **"Can an LLM reason about those locations and plan actions?"**

Then:

> **"Can a robot use foundation models to explore an unknown environment?"**

And increasingly:

> **"Can an embodied agent maintain a persistent, language-grounded belief about a changing world and use it to complete long-horizon tasks?"**

That final question is, in my view, the more interesting long-term problem.

---

# 17. Conclusion

Open-vocabulary navigation began with a relatively simple observation: pretrained vision-language models contain a semantic representation that is far more open-ended than the fixed object categories traditionally used in navigation.

VLMaps demonstrated how these representations could be grounded into spatial maps. ConceptGraphs moved toward more compact and structured representations by representing the environment as an open-vocabulary 3D scene graph. SayPlan demonstrated how structured spatial representations could provide an interface through which LLMs reason about large environments and generate high-level plans. OpenFMNav explored the other side of the problem: instead of assuming that a semantic map already exists, foundation models can actively guide exploration in unseen environments.

These approaches highlight two complementary capabilities:

**memory** and **reasoning under uncertainty**.

A robot operating in a real home needs both.

It needs memory because it should not have to rediscover its environment every time it receives an instruction. But it also needs to recognize that its memory can become outdated. It needs reasoning because the object described by a human may not have a fixed category or known location. And it needs active exploration because the world is only partially observable.

The eventual goal is therefore unlikely to be a static open-vocabulary semantic map or a purely reactive VLM navigation policy.

Instead, I believe the more general formulation is:

> **A robot should maintain a persistent, language-grounded and spatially grounded belief about its environment, continuously update that belief through perception and interaction, and use it to decide what to do next.**

In that formulation, open-vocabulary navigation becomes one component of a broader problem:

**building an embodied agent that can understand, remember, reason about, and act in a changing physical world.**

---

## Papers discussed

1. **VLMaps** — language-grounded visual maps for navigation and spatial reasoning.
2. **ConceptGraphs** — open-vocabulary 3D scene graphs for compact semantic representation and planning.
3. **SayPlan** — grounding LLM-generated task plans in large-scale 3D scene graphs.
4. **OpenFMNav** — open-set zero-shot object navigation using vision-language foundation models.
5. **Context-Aware Entity Grounding with Open-Vocabulary 3D Scene Graphs** — grounding free-form language to entities using contextual relationships.

The broader trajectory is from **semantic retrieval → spatial memory → language-based planning → active exploration → persistent embodied world models**.
